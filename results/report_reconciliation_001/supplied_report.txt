**System:** `chorus-hit-predictor` (binary classifier: year-end hit vs. other charted song, from 15-second chorus audio features)
**Repository:** https://github.com/DhanushSS/chorus-hit-predictor
**Report basis:** Repository README (setup, split design, reported metrics). Source files (`train.py`, `data.py`, `audio.py`) were not inspected; items marked **[VERIFY_IN_CODE]** require confirmation against source.
**Target metric:** Balanced accuracy ≥ **[TARGET_METRIC = 75%]**

## 1. Executive Summary

The system's balanced accuracy is statistically indistinguishable from random guessing on artist-disjoint data.

| Metric | Value | Source |
|---|---|---|
| Balanced accuracy (reported by user) | 53.3% | **[CURRENT_METRICS]** (user-supplied) |
| CV balanced accuracy (selected model, Polynomial SVM) | 53.6% | README |
| Test balanced accuracy | 46.6% | README |
| Test balanced accuracy, 95% bootstrap CI | 38.7% – 55.8% | README |
| Majority-class baseline | 50.0% | README |
| Test ROC-AUC | 0.456 (below chance) | README |
| Dataset | 751 songs, 518 features, 71 artists | README |
| Train / test | 597 songs, 52 artists / 154 songs, 19 artists | README |

The 21-point gap to target is not explained by a tuning deficiency. Three structural causes dominate:

1. **Weak target definition.** Both classes charted; the label separates "hit" from "near-hit," a distinction audio summary statistics barely encode.
2. **Insufficient data for the feature dimensionality.** 597 training samples against 518 correlated features; 52 training artists.
3. **Evaluation instability.** A 19-artist test set yields an interval of roughly ±8.5 points, so no model difference observed so far is reliable.

Additionally, artist-disjoint splitting (correctly implemented) removes the artist-identity shortcut. Any result near 75% obtained with a random or leaky split would be invalid.

Fourteen errors are cataloged below. Remediation should proceed in the order given in Section 4.

## 3. Remediation Plan

### E-01: Weak target definition

**Root Cause Analysis**
Class 1 = Billboard year-end hit; class 0 = sampled weekly Hot 100 songs not in the year-end set. Both populations are commercially successful. The decision boundary depends on promotion, artist fame, and timing rather than on chorus acoustics. The reference paper (CS229, 2021) used charted vs. never-charted, a wider contrast.

**Step-by-step technical fix**
1. Source a "never charted" negative set matching the positive set in era and genre distribution. Candidates: **[CANDIDATE_DATASET]**.
2. Define three targets and evaluate each with the same pipeline: (a) year-end hit vs. never charted, (b) charted vs. never charted, (c) peak chart position as regression.
3. Keep the current target (year-end vs. other charted) as a stratified secondary benchmark only.
4. Match class 0 to class 1 by release year (± 1 year) to avoid reintroducing E-10.

**Verification method**
- Run the unchanged pipeline on each target; compare balanced accuracy with artist-grouped CV.
- Run a label-permutation test (1,000 shuffles of labels within artist groups). The real score must exceed the 95th percentile of the null distribution.
- Success criterion: balanced accuracy on target (a) significantly above the 53.6% baseline (**[CURRENT_METRICS]**) with a CI lower bound > 50%.

### E-02: Unverified and potentially contaminated labels

**Root Cause Analysis**
Labels come from a third-party notebook. Exclusion of year-end hits from class 0 is by title; alternate titles, covers, remixes, and re-releases pass through. Weekly-chart sampling can include songs that were year-end hits in a different year.

**Step-by-step technical fix**
1. Normalize title + primary artist (strip "feat.", "remix", "version", punctuation, case) and re-check class overlap.
2. Cross-check every class-0 row against the full year-end list across all years, not only the matching year.
3. Fuzzy-match (Levenshtein ratio ≥ 0.9) on normalized title within the same primary artist; manually review flagged pairs.
4. Remove or relabel confirmed conflicts; record decisions in `data/provenance.json`.
5. Audit a random sample of **[SAMPLE_SIZE, e.g., 100]** labels against the original Billboard charts.

**Verification method**
- Report the count of removed/relabeled rows: **[CONTAMINATION_COUNT]**.
- Retrain; compare metrics before and after. Zero exact or fuzzy duplicate (artist, title) pairs across classes.
- Estimated label-noise rate from the audit sample reported with a Wilson 95% interval.

---

### E-03: Dimensionality exceeds sample support

**Root Cause Analysis**
518 features on 597 samples, strongly correlated within families. Flexible models (polynomial/RBF SVM, random forest, MLP) fit noise; CV score (53.6%) and test score (46.6%) diverge.

**Step-by-step technical fix**
1. Remove structurally redundant statistics: drop min/max/skew/kurtosis columns as a first ablation (518 → 222 features: mean, median, std for 74 channels).
2. Drop chroma CENS or chroma CQT, keeping one chroma family; re-measure.
3. Apply L1/elastic-net logistic regression inside the CV pipeline and retain non-zero coefficients; do not select features outside the CV loop.
4. Increase sample count (see E-01, E-14): target ≥ **[TARGET_SAMPLES, e.g., 3,000+]** songs and ≥ 300 artists.

**Verification method**
- Learning curve (train size vs. CV balanced accuracy): a curve still rising at full size confirms data is the bottleneck.
- Track CV-test gap; acceptance threshold: gap ≤ 3 points.
- Compare feature subsets using paired grouped-CV scores with identical folds.

### E-04: Underpowered test set

**Root Cause Analysis**
154 songs from 19 artists. Per-artist correlation inflates variance; the reported CI of 38.7–55.8% shows the test cannot distinguish 45% from 55%.

**Step-by-step technical fix**
1. Replace the single holdout with nested grouped CV: outer loop for performance estimation, inner loop for model selection.
2. Report the outer-fold mean and artist-cluster bootstrap CI.
3. After data expansion (E-01, E-14), reserve a holdout of ≥ 60 artists / ≥ 800 songs.

**Verification method**
- CI half-width ≤ 3 points on the final estimate.
- Confirm that no artist appears in both train and any evaluation fold (assertion in code).

---

### E-05: Incomplete artist grouping

**Root Cause Analysis**
Groups are normalized artist strings. "A feat. B", "A & B", "A", and aliases map to different groups, so the same artist's acoustic signature can sit in train and validation folds. This inflates CV and misstates generalization.

**Step-by-step technical fix**
1. Parse the artist field into primary artist and featured artists (split on "feat.", "ft.", "&", "with", "x", ",").
2. Assign the group ID to the primary artist; for conflicts, merge connected components (any song sharing any credited artist joins one group).
3. Maintain an alias table (**[ALIAS_TABLE_PATH]**) for known aliases and stage names.
4. Use `StratifiedGroupKFold` with the merged group IDs.

**Verification method**
- Automated test: for every fold, the set of credited artists in train and validation is disjoint.
- Compare CV score before and after regrouping; expect CV to fall toward the test score.

### E-06: Temporal structure discarded by summary statistics

**Root Cause Analysis**
Each of 74 channels is reduced to 7 scalar statistics over 15 seconds. Rhythm, build-ups, repetition, and dynamics over time are lost.

**Step-by-step technical fix**
1. Add beat-synchronous features: tempo, beat-strength statistics, onset-rate (librosa `beat_track`, `onset_strength`).
2. Add frame-level dynamics: RMS slope, spectral centroid slope, and 4-segment (≈ 3.75 s) segment means to capture within-clip progression.
3. Replace or supplement hand-crafted features with pretrained embeddings: **[EMBEDDING_MODEL]** (e.g., MERT, CLAP, PANNs, OpenL3). Mean-pool frame embeddings and train a regularized linear head.
4. Evaluate hand-crafted, embedding, and combined feature sets separately.

**Verification method**
- Ablation table: balanced accuracy by feature set with identical grouped-CV folds.
- Significance via paired bootstrap over artists (p < 0.05) against the 518-feature baseline.

---

### E-07: Redundant, heavy-tailed features and mismatched preprocessing

**Root Cause Analysis**
Chroma STFT/CQT/CENS encode overlapping information; skew, kurtosis, min, and max have extreme outliers. `StandardScaler` is outlier-sensitive and 95%-variance PCA is dominated by high-variance noise channels.

**Step-by-step technical fix**
1. Replace `StandardScaler` with `QuantileTransformer(output_distribution="normal")` or `RobustScaler` + clipping at the 1st/99th percentiles.
2. Remove PCA for linear models (use L2/L1 regularization instead); keep PCA only as a tuned option (`n_components` ∈ {20, 50, 100}) inside the grid.
3. Remove features with pairwise |correlation| > 0.95 inside each training fold.
4. Keep all steps inside the scikit-learn `Pipeline` so they fit on training folds only.

**Verification method**
- Compare CV balanced accuracy and fold-to-fold standard deviation before and after; target std ≤ 2 points.
- Check post-transform feature distributions (max |skew| < 2).

---

### E-08: Missing repetition and high-level musical features

**Root Cause Analysis**
The project premise ("repeated chorus") is not represented in the features. Tempo, key, mode, loudness, and duration are absent, though they are standard in hit-prediction literature.

**Step-by-step technical fix**
1. Compute a self-similarity matrix (chroma or MFCC) over the full track; derive repetition score, number of repeated sections, and chorus-length estimate.
2. Add chorus start position (fraction of track), chorus-to-track energy ratio, and integrated loudness (LUFS).
3. Add tempo, key, mode, and track duration.
4. Require full-track audio or equivalent metadata: **[AUDIO_SOURCE]**.

**Verification method**
- Permutation importance on grouped CV: new features must show non-zero importance with CI excluding 0.
- Ablation: base + repetition features vs. base only, paired bootstrap p < 0.05.

---

### E-09: Chorus extraction and feature-extraction mismatch

**Root Cause Analysis**
Training features come from the upstream pipeline (pychorus, original library versions, original audio). Inference uses a custom repetition heuristic and the current library environment. Zero-crossing is computed with a 22,050-sample frame length copied from upstream. Distribution shift between training and inference features is unquantified.

**Step-by-step technical fix**
1. Select one extraction configuration (sample rate, frame length, hop length, library versions pinned) and apply it to all training and inference audio.
2. Re-extract features from a source audio set **[AUDIO_SOURCE]** for training; do not mix upstream CSV features with locally extracted features.
3. Replace the zero-crossing frame length with the librosa default (2048) unless a documented reason exists.
4. Validate the chorus selector against **[N = 50]** manually annotated choruses; report overlap (IoU).

**Verification method**
- Extract features for **[N = 50]** songs with both pipelines; compute per-feature correlation and KS-test; flag features with correlation < 0.9.
- Chorus selector IoU ≥ 0.5 on the annotated set.

### E-10: Era confound and no temporal holdout

**Root Cause Analysis**
No release-date field. Production aesthetics drift by era; if class balance varies by year, the model learns era instead of hit quality, which fails on unseen artists and periods.

**Step-by-step technical fix**
1. Add release year from chart metadata (chart date for each row).
2. Check class balance per year; resample or weight so class ratio is constant per year.
3. Add a temporal holdout: train on years < **[CUTOFF_YEAR]**, test on years ≥ **[CUTOFF_YEAR]**, in addition to grouped CV.
4. Optionally include year as an explicit covariate, or evaluate with year-stratified folds.

**Verification method**
- Class ratio per year within ±5 points of the global ratio.
- Temporal-holdout balanced accuracy reported separately; compare with grouped CV to quantify era drift.

---

### E-11: Model selection among near-chance candidates on noisy CV

**Root Cause Analysis**
Nine candidates were compared on one 5-fold CV; scores differ by amounts below fold noise. The "winner" (Polynomial SVM) is selected by chance, and its test score (46.6%) shows regression to the mean.

**Step-by-step technical fix**
1. Compare candidates with repeated grouped CV (E-13) and a paired statistical test (Wilcoxon over repeats or Nadeau–Bengio corrected t-test).
2. Apply the one-standard-error rule: choose the simplest model within one SE of the best.
3. Default to a regularized linear model if no candidate is significantly better than baseline.
4. Add a majority-baseline and a shuffled-label baseline to every comparison table.

**Verification method**
- Selected model beats the shuffled-label baseline and majority baseline by a margin exceeding the CV SE.
- Selection reproducible across 3 different random seeds.

### E-12: Insufficient regularization and feature selection

**Root Cause Analysis**
With p ≈ n, hyperparameter ranges for C, γ, tree depth, and network size materially affect overfitting. The README does not report the search grids **[VERIFY_IN_CODE]**.

**Step-by-step technical fix**
1. Define explicit grids: logistic/linear SVM `C` ∈ [1e-4, 1e1] (log scale); RBF γ ∈ [1e-5, 1e-1]; random forest `min_samples_leaf` ≥ 5, `max_features` ∈ {sqrt, 0.1}; gradient boosting `max_depth` ≤ 3, `learning_rate` ≤ 0.05 with early stopping; MLP with weight decay and early stopping.
2. Run the search inside the inner loop of nested CV (E-04).
3. Add elastic-net logistic regression as a candidate.

**Verification method**
- Train-vs-validation score gap per model ≤ 5 points at the selected hyperparameters.
- Hyperparameter search results written to `results/cross_validation.csv` with the grid recorded.

### E-13: High-variance single-run CV

**Root Cause Analysis**
One partition of 52 artists into 5 folds gives a different result with a different seed; fold composition drives the score.

**Step-by-step technical fix**
1. Repeat `StratifiedGroupKFold` with **[N_REPEATS = 10]** different seeds.
2. Aggregate mean, SD, and a repeat-level CI.
3. Fix the seed list in config for reproducibility.

```python
from sklearn.model_selection import StratifiedGroupKFold
scores = []
for seed in range(10):
    cv = StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=seed)
    scores.append(cross_val_score(pipe, X, y, groups=g, cv=cv,
                                  scoring="balanced_accuracy"))
```

**Verification method**
- Across-repeat SD of mean CV score ≤ 1 point.
- Model ranking stable in ≥ 80% of repeats.

### E-14: Absent non-audio predictors

**Root Cause Analysis**
Chart outcome depends on genre, release timing, label promotion, artist following, and lyrics. The feature set contains only chorus audio statistics, which caps attainable accuracy regardless of model.

**Step-by-step technical fix**
1. Add genre and release-year metadata from **[METADATA_SOURCE]** (e.g., MusicBrainz, Spotify API, Last.fm).
2. Add lyric features (sentiment, repetition ratio, length) from **[LYRICS_SOURCE]**, respecting licensing.
3. Evaluate non-audio-only, audio-only, and combined models to quantify each source's contribution.
4. Exclude artist-popularity features if the goal is predicting hits for unfamiliar artists, as they change the problem; if included, document the change in scope.

**Verification method**
- Ablation table (non-audio / audio / combined) under grouped CV.
- Combined model must outperform the best single-source model with p < 0.05 (paired bootstrap over artists).
